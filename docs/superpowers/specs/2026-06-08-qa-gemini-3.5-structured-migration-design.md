# Q&A 遷移至 Gemini 3.5-flash 結構化串流 — 設計文件

> 最後更新：2026-06-08（Session 8）。範圍＝**只有 Q&A**；職涯推薦遷移為下一個獨立 spec→plan→impl 循環。

## Goal

把問答（`/qa/stream`、`/qa`）的生成模型從 `gemini-2.5-flash`（自由文字 + JSON-in-text 解析）遷移到 **`gemini-3.5-flash` 原生 structured output（`response_schema`）+ file_search + 串流**，以**從根本消除幻覺/citation 不一致**並簡化程式碼。保留 2.5 路徑為 env 可切的 fallback。

## Background / 為何現在做

- **Session 5 曾評估 3.5** → 當時 high-demand 503/延遲不穩，故留在「2.5 串流 + JSON 三層強化」。**現況已變**：3.5-flash 於 2026-05-19 I/O **GA**（非 preview）、output 速度 4×。
- **Session 8 診斷出兩個同源 bug**（grounding/citation）：
  1. 幻覺答案沒被擋（模型編「數位傳播科技與人工智慧」非真課，但內文通用詞「演算法」被 `extract_citations_by_name` 子字串誤配成真課 → citation 非空 → 防幻覺覆寫被繞過）。
  2. 好答案被誤覆寫（串流 grounding metadata 時有時無 + 名稱精確比對漏配 → citations 判空 → 觸發覆寫 → 已串流的好答案被「查無資料」蓋掉）。
  - 兩者根因＝**citation 偵測不可靠**（2.5 串流不能配 response_schema → 靠 JSON-in-text + 脆弱子字串比對）。
- **使用者決策**：靠 3.5 遷移**治本**（不另補 2.5 防禦補丁）；Q&A 先、推薦後；保留 2.5 fallback。

## 研究與實測（已驗證的關鍵假設）

以 context7 + web 研究，並用 live spike（真 Gemini，store=正式庫）實測「傳院有沒有 AI 課」：

1. **串流 + structured output + file_search 三者可同時成立**：串流 chunk 是「合法部分 JSON」，現有 `_partial_answer`（json_repair 增量解析）可直接抽 `answer` 值供打字機。
2. **grounding 穩定且正確**：course_ids=[`405935001` 跨媒體識讀、`402108001` 人工智慧進化史(廣告系)]，皆為 meta 真課、且正是答案表格主打課；跨掛取對版本（廣告系，非舊 name-matcher 誤選的商院版）。
3. **不幻覺**：表格課名都在 meta。
4. **`thinking_level="low"` 加速且安全**（實測對照）：

   | thinking_level | first-token | total | 回應非空 | grounding 存活 |
   |---|---|---|---|---|
   | medium（預設） | 14.5s | 16.3s | ✅ | ✅ |
   | **low（採用）** | **8.5s** | **11.6s** | ✅ | ✅ |
   | minimal | 10.0s | 13.2s | ✅ | ✅ |

   先前查到的「file_search+schema+thinking_config → nil + 掉 grounding」是 Gemini 3 **preview** 期問題，**3.5 GA 實測不觸發**（low/minimal 都回應非空、grounding 完整）。

## 架構

### 後端 `backend/qa.py`

新增 async 串流函式：

```
async def stream_answer_structured(client, store_name, question, history=None, model="gemini-3.5-flash"):
```

- `client.aio.models.generate_content_stream`，config：
  - `system_instruction=_SYSTEM_INSTRUCTION`（含「先檢索鐵則」，grounding-sensitive，沿用）
  - `temperature=0.2, top_p=0.95, max_output_tokens=4096`
  - `response_mime_type="application/json"`, `response_schema=_QA_RESPONSE_SCHEMA`
  - `thinking_config=types.ThinkingConfig(thinking_level="low")`（加速；實測 grounding 不掉）
  - `tools=[types.Tool(file_search=types.FileSearch(file_search_store_names=[store_name], top_k=5))]`
- `contents=build_qa_contents(question, history, template=_PROMPT_TEMPLATE_STRUCTURED)`（多輪歷史；用結構化精簡 template，不含 JSON 信封指示）。
- 串流迴圈：逐 chunk `_visible_text_from_chunk`（過濾 thought）累積 `raw`；用 `_partial_answer(raw)` 增量抽 `answer` 值，yield `{"event":"token","data":{"text": delta}}`（沿用現有 JSON-mode 增量邏輯）。
- 累積 grounding：每 chunk `_grounding_course_ids_from_chunk` → `done` 帶 `course_ids`（dedup 保序）+ `answer_text=raw` + followups（從完成的 JSON 解出）。
- 收尾仍由 main.py 呼叫 `finalize_qa_answer`（**不改動**：citations←grounding course_ids；空則 name fallback；列課+空 citation → no_match）。3.5 grounding 可靠 → 正常情況 citations 來自 grounding、覆寫只在「真查無」時觸發。

### 後端 `backend/main.py`

- env flag **`QA_MODEL`**：`"stream35"`（新預設）/ `"stream25"`（現有 2.5 `stream_answer` fallback）。
- `/qa/stream` 依 flag 選 `stream_answer_structured`（3.5）或 `stream_answer`（2.5）。**SSE 對前端的 `token` / `done` 合約不變**。
- `/qa`（POST，非串流 fallback）：沿用 `answer_question_structured`（已是 3.5 + schema），確保與串流一致；env flag 同步。
- 錯誤處理：沿用 `classify_qa_error`（429/503→rate_limited）；3.5 回 nil（理論上不會，但防禦）→ 視為空答案 → 既有空答案分支。

### 前端 `frontend/`

- **合約不變 → 改動最小**：`token`/`done`/`citations`/`no_match` 既有渲染（打字機 + progressive-md + citation 卡 + 復原）全沿用。
- 唯一須確認：first-token ~8.5s 期間有等待呈現（現有等待 UX；確保不空白卡住）。若體感不足再評估等待動畫，但**非本輪硬需求**。

## 資料流

```
/qa/stream?question=…  (QA_MODEL=stream35)
  → stream_answer_structured (3.5 + file_search + response_schema + thinking_level=low)
    → 逐 chunk：_partial_answer 抽 answer → SSE token（打字機）
    → 累積 grounding course_ids
    → done{course_ids, answer_text, followups}
  → main.py finalize_qa_answer(answer, followups, course_ids, meta)
    → citations（grounding 為主）/ no_match（真查無才覆寫）
  → SSE done{answer, citations, followups, no_match}  → 前端權威渲染
```

## 測試策略

### 1. 單元測試（確定性、TDD，不打 Gemini）

- `_partial_answer` 對部分 JSON 增量抽 `answer`（沿用既有測試 + 補 3.5 schema 形狀）。
- `stream_answer_structured` 用 mock async stream（造帶 grounding_metadata 的假 chunk）→ 驗 token 序列 + done course_ids。
- `finalize_qa_answer`：沿用既有 `test_qa_finalize`。
- `QA_MODEL` 分派：mock 兩條 stream 函式，驗 flag 正確選路。

### 2. 10 題品質驗收（GO/NO-GO 關卡，驗證階段對「實際端點」跑）

| # | 題目 | 風險面 |
|---|---|---|
| 1 | 傳院有沒有 AI 課 | bug 本案（單輪） |
| 2 | 我想了解資料科學相關課程 | 核心領域 + 表格 |
| 3 | 想當 PM 要修什麼課 → 追問「那金融呢」 | 多輪脈絡 grounding |
| 4 | 法律系有哪些科技/智財相關的課 | 法律×科技跨域 |
| 5 | 有沒有適合零程式基礎的人的課 | 條件約束 |
| 6 | 商院有沒有永續/ESG 課 | 政大強項 |
| 7 | 教我寫一首詩 | 離題→溫和導回（不編課） |
| 8 | 政大宿舍怎麼申請 | 大學相關非課程→邊界 |
| 9 | 有沒有量子重力的課 | 真查無→誠實，**絕不幻覺** |
| 10 | 外語學院有哪些跨文化/國際商務的課 | 政大強項 + 跨掛正確 |

判定（雙軌）：
- **確定性（硬性、零容忍）**：答案/表格列出的每門課名都是 `courses_meta.json` 真課 → **幻覺數＝0**；列課時 citation 非空且對應主打課；好答案不得被誤覆寫成查無；第 9 題須走 no_match 不可編課。
- **LLM judge**（`qa_judge.py` RAGAS 3 維）：分數 ≥ 2.5 基線或絕對門檻。
- **延遲**：total 中位數 ≤ ~16s、first-token ≤ ~10s。

GO/NO-GO：**10/10 零幻覺**（一題破即 NO-GO）+ 7/8/9 邊界正確 + 無誤覆寫 + judge 不低於基線。未過→不上線、保持 2.5 fallback。

### 3. Playwright MCP 端到端

代表性 2-3 題（含第 1、3、9 題）走真前端：答案串流出、citation 正確、不被複寫、不幻覺、0 console error。

## 風險與緩解

- **3.5 延遲/503 抖動**：env flag 可即時切回 2.5；驗證階段量延遲穩定度。
- **grounding 在某些 query 仍可能空**（多輪/冷門）：`finalize_qa_answer` 的 no_match 覆寫作為誠實兜底；10 題第 9 題專測。
- **thinking_level=low 在罕見 query 品質下降**：10 題 judge 把關；不過則升回 medium 或維持 2.5。
- **單次 spike 樣本少**：驗證階段每題多跑確認穩定度。
